The Problem

Leads go cold — fast

Inbound leads lose interest within minutes of filling out a form. Most sales teams can't respond fast enough, and when they do, reps waste time on unqualified prospects. Hiring a full SDR team to handle qualification isn't viable for most companies.

This system solves that by placing an AI-powered phone call automatically — no human trigger required — the moment a HubSpot deal reaches the qualifying stage.

High Level Overview

What it does in one sentence

When a deal moves to the right stage in HubSpot, the system automatically calls the prospect, has a live AI qualification conversation, and logs a structured note back into HubSpot — then alerts the AE in Slack if the lead qualifies.

End-to-end flow

In Depth

How each piece works

ZAP 1 HubSpot Deal Stage → Vapi Call

This Zap is the outbound trigger. It runs entirely behind the scenes the moment a deal is moved.

  • 1

    HubSpot — Updated Deal (trigger)

    Polls HubSpot for deal changes. A filter step checks that the deal stage matches the target ID — any other stage change is ignored.

  • 2

    HubSpot — Find Associated Contact

    The deal trigger doesn't include contact data. This step looks up the contact linked to the deal and pulls name, phone, email, company, and lead source.

  • 3

    Formatter by Zapier — Format Phone to E.164

    Vapi requires phone numbers in E.164 format (+15551234567). HubSpot stores them inconsistently — this step normalises the number before the API call.

  • 4

    Webhooks by Zapier — POST to Vapi /call/phone

    Fires the call. Passes the prospect's phone, name, and email in the customer object. Passes company and lead source via assistantOverrides.variableValues so the AI can reference them in conversation. The HubSpot deal ID is stored in metadata so Zap 2 knows which deal to update.

VAPI AI Voice Agent — Marcus

Vapi handles the actual phone call using a pre-configured AI assistant. The system prompt is templated — all prospect data injected at call time from Zap 1.

VariableSourceUsed for
{{customer.name}}HubSpot contactPersonalised greeting
{{customer.email}}HubSpot contactConfirmed at end of call
{{company}}HubSpot contactReferenced during intro
{{leadSource}}HubSpot contactContext for how they came in

The AI asks three qualification questions: current Google Ads usage, business type, and decision-making authority. At the end of the call it confirms the best email on file. The full transcript is sent to Zap 2 via webhook when the call ends.

ZAP 2 Vapi Webhook → HubSpot Note + Slack

This Zap is always listening. It receives every Vapi event, filters to just the end-of-call report, and processes the result.

  • 1

    Webhooks — Catch Hook (trigger)

    Receives all Vapi events. Immediately filtered so only end-of-call-report events continue — transcript chunks and status pings are dropped.

  • 2

    Code by Zapier — Extract Deal ID

    Zapier's HubSpot trigger returns a compound string instead of a plain deal ID. A single line of JavaScript extracts the real ID: compound.split('-')[0].

  • 3

    AI by Zapier — Generate Structured Call Note

    Feeds the raw transcript into an AI prompt that produces a clean, professional note with five sections: Pain Point, Objection, Qualification Signal, Next Step, and Disposition. The AI paraphrases — it does not quote verbatim.

  • 4

    HubSpot — Create Note Engagement on Deal

    Posts the AI-generated note directly to the deal in HubSpot. Associated via the extracted deal ID. Any AE viewing the deal sees the full call summary immediately.

  • 5

    Filter — Qualified only

    Checks Vapi's successEvaluation field. Only qualified leads continue to Slack. Unqualified calls still get their HubSpot note — the AE just isn't pinged.

  • 6

    Slack — Send Channel Message to #ae-leads

    Posts a formatted alert with contact name, deal name, all five AI note sections, and a direct link to the HubSpot deal. The AE can react to claim the lead or reply in thread.

Challenges Encountered

What broke and how we fixed it

Building this surfaced several non-obvious Zapier, HubSpot, and Vapi quirks. Here are the most significant ones.

1. HubSpot deal ID was a compound string, not a plain number

Zapier's HubSpot "Updated Deal" trigger returns a value in the format dealId-stageId-timestampMs (e.g. 58208201305--1780009240278). We assumed the last segment was the deal ID — it's actually a Unix timestamp in milliseconds. HubSpot's API rejected every attempt to create an engagement because the ID was invalid.

Fix: Added a Code by Zapier step with compound.split('-')[0] to extract the first segment, which is the real deal ID.

2. Zapier filter was pointing at a blank placeholder field

The filter checking for end-of-call-report was configured against a generic "Field 1" with no data. Every call was being silently filtered out — no errors, no Zap runs, just nothing happening.

Fix: Re-mapped the filter to the correct field by searching the dropdown for the field whose sample value was end-of-call-report. Zapier flattens nested JSON field names, so the correct field appeared as "Message Type" not message.type.

3. HubSpot engagement association silently failing

Notes were being created in HubSpot but not linked to any deal. The haltIfAssociationsErrors setting was false by default — HubSpot was swallowing the association error and creating orphaned notes.

Fix: Set haltIfAssociationsErrors to true to surface the real error. Separately, the dealIds field was in "line item" mode which injected a stray index 1 alongside the deal ID — switched to Custom mode to pass a single plain value.

4. Email, company, and lead source not reaching the AI assistant

The Vapi system prompt referenced {{customer.email}}, {{company}}, and {{leadSource}} — but Zap 1 was only sending number and name. The AI was confirming a hallucinated email address at the end of every call.

Fix: Added email to the customer object in the POST body. Added company and leadSource via assistantOverrides.variableValues — this is Vapi's mechanism for injecting custom variables into a system prompt at call time.

5. AI call notes were vague and repetitive

The AI by Zapier step was receiving message.summary (Vapi's pre-generated summary) as its input and just echoed it back. The notes contained raw transcript quotes and were not useful to an AE.

Fix: Switched the input to message.transcript (the full raw conversation) and rewrote the prompt to instruct the AI to paraphrase in professional language across five structured sections. The AI now produces clean, actionable notes a rep can act on immediately.

6. Duplicate Zap 2 runs per call

Vapi fires multiple webhook events to the same URL during a single call — call started, transcript chunks, and end-of-call report. Without a filter, Zap 2 was triggering on every event, creating multiple partial notes per call.

Fix: Added a Filter by Zapier step immediately after the trigger: only continue if message.type exactly matches end-of-call-report. All other events are dropped before any actions run.

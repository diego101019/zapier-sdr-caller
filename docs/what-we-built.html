Zapier SDR Caller — What We Built

A no-code Zapier automation that replicates a production Make.com workflow: when a HubSpot deal moves to a specific pipeline stage, an AI voice agent (Vapi) automatically calls the prospect, runs a qualifying conversation, and logs the call summary and transcript back to HubSpot as a call engagement note.

No application code was written. The entire project is Zap configuration, Vapi assistant configuration, and HubSpot configuration.

Architecture — 2 Zaps

HubSpot Deal (stage change)
  → deal ID, associated contact ID
    → contact phone number (via HubSpot lookup)
      → Vapi call triggered (deal ID passed in metadata)
        → call ends, Vapi webhook fires (deal ID in payload)
          → HubSpot call note created on deal

Zap 1 — "Trigger Vapi Call on Deal Stage Change"

  • Trigger: HubSpot — Updated Deal → Filter: dealstage equals
  • Action 1: HubSpot — Find Associated Contact (gets phone number from the deal's linked contact)
  • Action 2: Webhooks by Zapier — POST to https://api.vapi.ai/call/phone

Vapi POST body:

{
  "assistantId": "",
  "phoneNumberId": "",
  "customer": {
    "number": "<phone from contact lookup>",
    "name": "<contact name>"
  },
  "metadata": {
    "hubspot_deal_id": "<deal ID from trigger>",
    "hubspot_contact_id": "<contact ID from Action 1>"
  }
}

The metadata object rides with the call and comes back in the Vapi webhook — this is how Zap 2 knows which HubSpot deal to update.

Zap 2 — "Log Vapi Call Result to HubSpot"

  • Trigger: Webhooks by Zapier — Catch Hook (URL: )
  • Filter: Only continue when message.type equals end-of-call-report
  • Action 1: Formatter by Zapier — build structured note from transcript, summary, and disposition
  • Action 2: HubSpot — Create Engagement (Call) on the deal

Key fields extracted from the Vapi webhook payload:

  • message.call.metadata.hubspot_deal_id — which deal to update
  • message.summary — AI-generated call summary
  • message.transcript — full call transcript
  • message.endedReason — disposition (e.g., customer-ended-call)
  • message.analysis.successEvaluation — Vapi's qualified/not-qualified assessment
  • message.durationSeconds — converted to ms for HubSpot engagement duration

HubSpot engagement is created as type Call, direction Outbound, status Completed, associated to the deal by ID.

Key Technical Decisions & Gotchas

  1. Build Zap 2 first. You need the Catch Hook URL before you can register it in Vapi, and you need it registered before Zap 1 can be end-to-end tested.
  2. HubSpot deal trigger doesn't include contact data. Zapier's native deal trigger gives you the deal but not the associated contact — a separate "Find Associated Contact" lookup step is required, adding to task usage.
  3. Polling delay. Zapier polls HubSpot every 5–15 minutes (not instant). Mitigation: use a HubSpot Workflow to push a webhook to a Zapier Catch Hook instead, making Zap 1 event-driven.
  4. Phone number format. Vapi requires E.164 format (+15551234567); HubSpot stores numbers inconsistently. Formatter by Zapier normalizes this between the contact lookup and the Vapi POST.
  5. Vapi fires multiple event types to the same server URL (call.started, transcript chunks, end-of-call-report). A Filter step in Zap 2 gates on end-of-call-report to avoid multiple Zap runs per call.
  6. Zapier's field mapper needs a real sample. To map nested fields like message.call.metadata.hubspot_deal_id, Zapier needs to have seen the payload. Workaround: POST a mock end-of-call-report payload via curl/Postman to the Catch Hook URL to train the field mapper before making a live call.
  7. Duplicate call prevention. If a deal stage is toggled back and forward, Zap 1 fires again. Solution: add a HubSpot deal property (ai_call_triggered), filter in Zap 1 to halt if it's already set, then update it after triggering the call.
  8. Task budget. ~3 tasks per Zap run → ~6 tasks total per prospect called.
